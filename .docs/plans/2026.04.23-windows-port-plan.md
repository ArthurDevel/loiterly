# Windows Port Plan

## Goal

Ship a Windows build of the Electron app with the same core product behavior as macOS:
- tray-based app shell
- frameless always-on-top workspace window
- companion bubble
- Conductor and prompt integrations
- installable Windows packaging and update path

This plan is written so a new agent can pick it up without prior context.

Instructions:
- After each phase, check the completed boxes in this document.
- When new findings pop up, add them to this document before or during implementation.

## Current State

- The app is Electron-based and the Swift app has already been removed.
- Packaging and release automation are macOS-only.
- Auto-update is effectively macOS-only.
- Conductor integration uses a macOS-specific DB path and shells out to `sqlite3`.
- The companion input monitor is implemented as a macOS-only Swift helper.
- Some window behavior is tuned for macOS Spaces and needs Windows-specific handling.

## Tradeoffs And Technical Implications

- A Windows native helper is the right choice if we want companion behavior close to macOS. Without it, typing suppression and cursor-adjacent companion behavior will be weaker or inconsistent.
- The "phases" below are implementation checkpoints, not separate product releases. We can still do this in one branch and ship it together.
- Bundling or replacing the `sqlite3` dependency matters. Relying on a system-installed `sqlite3` is fragile on Windows.
- Always-on-top, transparent, frameless windows work on Windows, but their exact behavior needs hardware testing across DPI scaling and multi-monitor setups.
- Windows auto-update is easiest if we adopt `electron-builder` + `nsis` cleanly and align release assets with `electron-updater`.

## Findings

- The old native Swift app target has already been removed from the branch after merging `origin/main`.
- The remaining Swift code is only the macOS-native companion helper under `electron/native/companion-input-monitor.swift`.
- Current Windows effort is moderate because the product shell is already in Electron; the main remaining work is platform plumbing rather than a rewrite.
- The Windows helper is implemented as a compiled C# `winexe` so Electron can spawn it without flashing a console window.
- Windows Conductor reads now avoid a system `sqlite3` dependency by using `node:sqlite` on Windows while preserving the existing CLI path elsewhere.
